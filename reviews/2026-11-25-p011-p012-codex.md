## Round 1: P-011 (rev 1)

- **P1 — Rule 4 should default to preserving the logical ID, with history governed separately.** Same-name recreation can preserve a bookmark while restarting a grace period or a `since` clock that measures the current incarnation or episode. The draft says recreation keeps history, and its exception only says where to store the marker. Snellius already keys grace periods by `(UID, generation)`. Its fallback `since` resets on restart or an observed gap and can carry over if replacement happens without a gap. Rule 1 should leave timestamps out of its durability guarantee. [Draft](kgateway-tooling draft (pre-commit)) · [Snellius design](snellius/docs/phases/phase-3/design.md:127) · [8.1 review](snellius/docs/phases/phase-8/reviews/8.1-ids-codex.md:13)
- **P1 — Rules 1–3 need to explicitly permit correlation across observations of the same incarnation.** Allow UIDs to key incarnation-scoped state and verify capture sources. That covers Snellius grace periods, restart holds and per-Pod counter deltas, and kgwctl’s post-capture Pod recheck. A generation, resourceVersion or content hash tracks revision or content and can change within one incarnation. Scope the UID ban to logical IDs that must survive replacement. D-102’s install URLs and D-132’s finding IDs fit that rule. [Restart hold and deltas](snellius/docs/phases/phase-3/design.md:336) · [Bundle identity check](kgwctl/docs/decisions.md:214) · [D-102](snellius/docs/decisions.md:1530)
- **P1 — Rule 3 should explicitly bar ordinal and rank discriminators in durable IDs.** Sorting first still lets sibling insertion, removal or visibility changes rekey a surviving finding. That was the D-040 failure D-132 fixed for policy-ancestor KGWUI-002. The UID alternative was rejected before shipping, and other D-040 ranks remain to audit. xdsview’s occurrence IDs are valid within their originating dump. [D-132](snellius/docs/decisions.md:1821) · [Option C](snellius/docs/phases/phase-8/reviews/8.1-ids-codex.md:23) · [P-010](kgateway-tooling/program.md:198)
- **P2 — Require a stable key within a declared scope.** Include cluster or install scope where keys cross those boundaries. Generated Pod names churn, and control-plane-generated Envoy names can change or collide. A rename changes a name-based key unless an explicit alias or migration preserves it. For unnamed entities, use a producer-guaranteed stable discriminator if one exists. Otherwise keep identity snapshot-local and report ambiguous or unknown matches. Use xdsview’s existing provenance mapping for runtime-to-declared joins. [P-010](kgateway-tooling/program.md:198) · [Ownership](kgateway-tooling/program.md:214)
- **P2 — Keep P-011 and the guidelines in `program.md` and add a review-time read to the coordination protocol.** The existing protocol reaches repo sessions at phase start. Standalone reviewers and sessions already underway need the current decision linked in their briefs or prompts. A coordination-repo `AGENTS.md` alone has local scope. [Coordination protocol](kgateway-tooling/program.md:261)

## Round 2: P-012 (rev 1)

- **P1 · Rules 1–3 miss compatibility changes outside CRDs.** Keep the CRD diff where applicable and review the versioned interfaces each tool consumes in the same bump. xdsview has no CRDs. It reads policy refs generically, but its `TrafficPolicy` field-to-filter attribution and Envoy filter-type table can go stale with an empty CRD diff. Include xdsview explicitly and use controller output or Envoy fixtures to check those mappings. [P-012 draft](kgateway-tooling draft (pre-commit)) · [Policy attribution](xdsview/pkg/envoy/origin/kgateway.go:302) · [Filter types](xdsview/pkg/envoy/chain/sides.go:10)
- **P1 · Rule 4 contradicts rule 2’s recorded exclusions.** kgwctl’s guard checks RBAC only for served fixture kinds within the bundle’s scope. Snellius’s Helm test checks grants against its supported kind registry, and its API explicitly tests that `UDPRoute` has no detail view. Require coverage of each list’s intended scope. Accept existing behavioral tests and recorded exclusions, and allow a documented exception with a fallback check when no authoritative test input exists. xdsview already tests filter types against real dumps. [kgwctl guard](kgwctl/internal/testenv/rbac_guard_test.go:61) · [Snellius Helm test](snellius/deploy/helm/chart_test.go:129) · [UDPRoute test](snellius/pkg/api/details_test.go:604) · [xdsview dump test](xdsview/pkg/envoy/parser/accuracy_e2e_test.go:50)
- **P2 · Rule 3 leaves removals and storage versions implicit.** Call out removed kinds and versions so stale watches and version mappings get reviewed. Carry over the kgwctl checklist’s storage-version and Secret-reference checks. [kgwctl bump checklist](kgwctl/internal/testenv/testdata/crds/README.md:24)
- **P2 · A new supported minor needs an explicit mirror check.** Snellius can fall back to its 2.5 rules for a newer controller. A CRD diff can pass while M-1’s route logic or M-4’s discovery semantics have changed. Have the bump invoke the existing mirror rules before claiming support for the new minor. Those rules already require updating the pins and recording conformance against real controller output per minor. [Rule selection](snellius/pkg/computed/rulesets/rulesets.go:21) · [Program mirror rules](kgateway-tooling/program.md:135)
